# October 2026 experiments

## Judge-only screening (2026-10-01) — Ministral 14B, local candidate

`ml.evaluate_judge` with judge v6 on the same 95 single-Claim cases from
`eval_gold_extractor_v5.jsonl`. Mistral models through its API; `llama3.2` is the format
test from 2026-09-30 (Ollama, one field per Source), on the same cases:

|                  | `llama3.2` | `ministral-14b-2512` | `ministral-3:14b` (Ollama) | `mistral-small-2603` |
| ---------------- | ---------- | -------------------- | -------------------------- | -------------------- |
| judged           | 95         | 93                   | 95                         | 95                   |
| firm             | 71         | 71                   | 77                         | 68                   |
| correct          | 46 (65%)   | 65 (91.5%)           | **72 (93.5%)**             | 66 (97.1%)           |
| falsa→verdadera  | 22         | 4                    | **1**                      | 1                    |
| verdadera→falsa  | 3          | 2                    | 4                          | 1                    |
| s:c on true      | 3.8        | 22.2                 | 15.1                       | 27.8                 |
| s:c on false     | 1.8        | 0.18                 | **0.05**                   | 0.09                 |

- **`mistral-small-latest` is no longer a deployable candidate.** Today it is
  `mistral-small-2603` (Small 4), which weighs 119B in Ollama and does not fit in a
  16 GB VM; it is probably also the `mistral-small` behind the 0.58 of 2026-08-31. The
  API no longer serves Mistral Small 3.x (24B), so that family cannot be screened
  through the API.
- **`ministral-14b-2512` is the same weights as `ministral-3:14b` in Ollama** (~9 GB at
  Q4), the only deployable candidate the API lets us screen, and it separates almost as
  well as Small 4: with the same 71 firm verdicts as `llama3.2`, 4 falsa→verdadera
  instead of 22.
- Its 2 unjudged cases are `ValidationError`s: the API does not constrain output to the
  schema and the response fails validation. With Ollama the schema is enforced during
  generation.
- **Confirmed on Ollama**: `ministral-3:14b` with its default quantisation judges all 95
  (the schema is enforced during generation) and calls 1 false Claim of 77 firm
  verdicts `verdadera`. It takes ~11 GB loaded with `num_ctx` 8192; on a laptop with no
  usable GPU, ~70 s per case.
- The gold set is in-sample: what counts is the comparison between judges, not the
  93.5%.
- Cost: ~€0.07 per 95-case run with the Mistral API.

## Analysis Verdict from Claim Verdicts: `parcialmente falsa` (2026-10-12) — adopted

A fix to the Analysis Verdict, not to the judge. Averaging the falsehood score of the
Claims with Evidence lets a well-supported true Claim offset a false one. With Mistral
Small, the text "drinking diluted bleach kills the virus" + "a paracetamol overdose
causes liver damage" comes out **verdadera**: bleach false (0.67), paracetamol true
(0.17, four `supports`), average 0.42. Another text with refuted homeopathy and two true
Claims, the same. The single-Claim gold set cannot see it: with one Claim, the average
is that Claim.

The Analysis Verdict now follows from each Claim's Verdict (ADR-0002): false and true
Claims together give `parcialmente falsa`, with the Confidence of the strongest false
Claim. Single-Claim results do not change. In `evaluation.evaluate_pipeline`,
`parcialmente falsa` counts as a falsehood warning (positive), like `falsa`. A gold-set
row the extractor splits into two Claims can produce it.

Open: a multi-Claim set (15–20 texts with their key Claims and the expected Analysis
Verdict) to measure this rule and the extractor's trimming.

## Full pipeline on Mistral pay-as-you-go, the production config (2026-10-13)

The first full gold run since 2026-08-31, and the first on the current code: judge v6,
extractor and translator v5, and the `parcialmente falsa` rule. It measures what
production will serve: Mistral pay-as-you-go with training opted out,
`mistral-small-latest` in all four roles, git `b045d74`. The explanation was on, so
latency and cost are a user's; it does not decide the label. Evidence was searched live
and the 2026-08-31 checkpoint no longer exists, so the comparison is not paired.

```bash
uv run --directory backend --extra evaluation python -m evaluation.evaluate_pipeline --partition gold --limit 100 --with-explanation --checkpoint results/gold_mistral_payg_2026-10-13.jsonl
```

|                      | 2026-08-31 (judge v3) | 2026-10-13 (judge v6) |
| -------------------- | --------------------- | --------------------- |
| accuracy             | 71/100                | 70/100                |
| firm verdicts        | 77                    | 77                    |
| **accuracy on firm** | **92.2%** (84–96%)    | **90.9%** (82–96%)    |
| recall on false      | 25/50                 | 23/50                 |
| falsa→verdadera      | 6                     | 5                     |
| verdadera→falsa      | 0                     | 2                     |
| false: s:c           | 0.24                  | 0.32                  |

Wilson 95% intervals in brackets. Juez caído: 0.

- **Flat.** The same 77 firm verdicts, one fewer right, and intervals that almost
  coincide: the code since August neither cost quality on this set nor bought any.
- **The errors are stable.** `evaluation.evaluate_judge` re-judged the 93 single-Claim
  rows on this run's recorded Evidence (`results/judge_mistral_payg_repeat_2026-10-13.jsonl`):
  71 firm, 64 right (90.1%), 4 falsa→verdadera, 3 verdadera→falsa. 85 of 93 verdicts
  match and 6 of the 7 errors below repeat. At temperature 0 the judge still changes
  about 1 verdict in 12 on identical Evidence; that is the noise floor for any comparison
  on this set.
- **In 4 of the 5 falsa→verdadera, the judge marks Sources that refute the Claim as
  `supports`.** On «Las vacunas infantiles … causan autismo», «Vaccines are not associated
  with autism» (a meta-analysis), the nationwide MMR cohort and «The MMR Vaccine and
  Autism» are all `supports`, and a 2026 aluminium reanalysis that reports an association
  is `contradicts`: the polarity is fully inverted, in both runs. Three cardiovascular
  reviews, two recommending statins for prevention, support «Statins do not reduce the
  risk of heart attack»; three reviews, one saying the virus spreads «through asymptomatic
  carriers», support «Asymptomatic individuals cannot transmit coronavirus»; two reviews
  calling for photoprotection in skin of colour support «People with dark skin do not
  need sun protection». The judge rates agreement with the topic's consensus, not with
  the Claim: the failure 2026-09-30 recorded for `llama3`, now with `mistral-small`. The
  translator kept every negation.
- **Negated Claims carry most of it.** 9 rows contain no, nunca or ningún; 4 are wrong,
  against 3 of 68 firm affirmative rows; Fisher one-sided p = 0.003 (0.018 in the
  repeat). Three of the four are the inversion above. The fourth, «Los ensayos clínicos no
  han demostrado que la homeopatía supere al placebo» → `falsa`, is retrieval: two of its
  three Sources (a 2026 add-on trial in lung cancer and a 2023 review of meta-analyses) do
  report effects beyond placebo and were read right; only «Are the clinical effects of
  homoeopathy placebo effects?», which concludes they are, was misread. The set has few
  negations and was not built to test them: a mechanism seen in two runs, not a rate.
- **Latency**: 14.3 s median, 18.7 s p90 and 23.5 s max per sample, extractor to
  explanation, on a home connection with no queue. 93 samples have one Claim, 7 have two.
- **Cost**: 407 calls (100 extractor, 100 translator, 107 judge, 100 explanation),
  634,522 input and 162,926 output tokens: $0.19 at the Small 4 list price ($0.15 / $0.60
  per 1M), or $0.0019 per sample (6.3k in, 1.6k out). Tokens come from each response's
  `usage`, tallied by a throwaway wrapper around `main()`; the harness ran unchanged. The
  response names the model `mistral-small-latest`, not a snapshot; per 2026-10-01 the
  alias is `mistral-small-2603`.
- **Mistral rate limit**: the re-judge sends judge calls back to back and hit 429 «Rate
  limit exceeded» in two of its three passes; the pipeline, at about 4 calls per 14 s,
  never did. Check the workspace limit before raising `WORKER_MAX_JOBS`.
- **PubMed**: 6 of 107 searches failed. The investigator logs the failure without the
  exception, so the cause is unknown; no Claim lost all its Sources.
- The one `parcialmente falsa`, «La sal marina no aporta sodio y puede consumirse sin
  límite en la hipertensión», is a falsa row the extractor split in two; it counts as a
  hit.

Open: the inversion. The 2026-09-01 lesson holds (a prompt that makes the judge more
decisive is a coin flip), so a fix has to target polarity and be measured on a set built
for it, with negated pairs and consensus Sources for false Claims, and criteria fixed
before measuring.
